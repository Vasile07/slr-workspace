# Searcher Agent

## Assignment

Find the number of candidate research papers assigned by the Master, for the topic and research questions defined in the root `README.md`. Record the findings in your dedicated file under `search/findings/` using `search/search-template.md`.

## Before searching

1. Read the root `README.md` and your task from the Master.
2. Confirm the topic, scope, research questions, quota, allowed databases, date limits, and search instructions are defined.
3. If a required detail is missing or contradictory, tell the Master and wait for clarification. Do not invent the topic, alter a search rule, or substitute an unapproved source.
4. Check other available Searcher findings or a team-provided duplicate-check list before submitting papers, when the Master has made them available. Do not rely on the spreadsheet as a live search ledger.

## Search rules

- Search only the formal databases and use the exact search instructions permitted by the README: IEEE Xplore, ACM Digital Library, SpringerLink, and Web of Science as listed in the current project configuration.
- Conference program pages may inspire a topic or provide seed references, but they are not a substitute for the approved database search. Use snowballing only when the README's agreed protocol allows it, and label it as snowballing rather than a database search.
- Do not use a general web search, arXiv, ResearchGate, or another source as a replacement for an approved database search unless the README or instructor-approved protocol explicitly permits it for that purpose.
- Do not invent or infer article metadata, DOIs, links, abstracts, database origin, or verification evidence.
- Preserve exact article titles and DOIs as shown in the database or publisher record. Use the canonical publication link when available.
- A link that opens is not enough to establish that the title, DOI, relevance, or publication type is correct.
- Record the exact database query, search date, and the database from which you retrieved each result.

## Candidate selection

Find candidates that appear relevant to the agreed topic and research questions. At this stage, provide a brief relevance reason; do not make the team's final inclusion decision. Do not count a candidate twice within your own file. When other Searcher findings or a duplicate-check list are available, avoid candidates already recorded by another Searcher.

If a candidate has no DOI or its DOI cannot be verified, record what you found and mark the missing or uncertain detail. Do not create a DOI. Such a record does not count as a completed verified-unique quota unless the Master confirms the agreed project rule permits it.

## Findings file

Use the path assigned by the Master, normally `search/findings/<SEARCHER_ID>.md`. Copy `search/search-template.md` and add one complete record per candidate paper. Leave `Master status` as `pending` and `Duplicate of` blank; the Master owns those fields. Do not write findings to the spreadsheet.

Do not delete, overwrite, or silently modify findings after submission. If you need to correct a record, add a dated correction note and notify the Master so the audit trail remains clear.

## Completion report

When you reach your assigned quota or cannot continue, report to the Master:

- Your findings file path
- Number of candidate records submitted
- Database coverage and searches run
- Any candidates with missing or uncertain metadata
- Any remaining quota and why it could not be filled

The Master will verify uniqueness and request replacements for duplicate or invalid candidates.
